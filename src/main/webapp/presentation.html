🚨 The Problem

Traditional Perimeter Security is Dead

  • Cloud adoption dissolves network boundaries
  • Remote work expands attack surface
  • Lateral movement after breach is common
  • Single authentication at entry is insufficient

Real-World Impact

A healthcare breach exposed 5M+ patient records because attackers moved laterally after initial access. Traditional "castle-and-moat" security failed.

🎯 Zero Trust Principles

Never Trust

  • No implicit trust
  • Every request validated
  • Location doesn't matter

Always Verify

  • Continuous validation
  • Context-aware decisions
  • Least privilege access

Core Tenets

  1. Verify explicitly - Always authenticate and authorize
  2. Least privilege - Limit access with just-in-time/just-enough
  3. Assume breach - Minimize blast radius and segment access

🔑 Authentication: The Hard Way

Building a Custom `HttpAuthenticationMechanism`


@ApplicationScoped
public class JwtAuthenticationMechanism implements HttpAuthenticationMechanism {
    public AuthenticationStatus validateRequest(...) {
        // 1. Manually get "Authorization" header
        String authHeader = request.getHeader("Authorization");

        // 2. Manually parse the Bearer token
        String token = authHeader.substring("Bearer ".length());

        // 3. Manually fetch Keycloak's public keys (JWKS)
        JWKSet jwkSet = fetchJwkSetFromKeycloak();

        // 4. Manually verify the JWT signature
        if (!verifySignature(signedJWT, jwkSet)) { ... }

        // 5. Manually validate claims (issuer, expiration)
        if (isExpired(jwt) || !isValidIssuer(jwt)) { ... }

        // 6. Notify container of the result
        return httpMessageContext.notifyContainerAboutLogin(result);
    }
}

This is complex, error-prone, and requires deep security knowledge.

🔑 Authentication: The Standard Way

Jakarta Security + MicroProfile JWT

Configure JWT validation in `microprofile-config.properties`:


mp.jwt.verify.publickey.location=http://localhost:8180/realms/jdd-poland/protocol/openid-connect/certs
mp.jwt.verify.issuer=http://localhost:8180/realms/jdd-poland
mp.jwt.verify.audiences=jdd-healthcare-app

Implement Jakarta Security's standard authentication mechanism:


@ApplicationScoped
public class JwtAuthenticationConfig implements HttpAuthenticationMechanism {
    @Inject private JsonWebToken jwt; // Validated by MP-JWT!

    public AuthenticationStatus validateRequest(...) {
        if (jwt != null && jwt.getName() != null) {
            return httpMessageContext.notifyContainerAboutLogin(
                jwt.getName(), jwt.getGroups()
            );
        }
        return httpMessageContext.doNothing();
    }
}

Standard Jakarta Security + Automatic JWT Validation

MP-JWT validates the token, you just integrate with Jakarta Security's auth flow.

🛡️ Authorization: The Hard Way

Custom Annotations and Interceptors

1. Create a custom annotation:


@InterceptorBinding
@Retention(RUNTIME)
@Target({METHOD, TYPE})
public @interface RequireRole {
    String[] value();
}

2. Create an interceptor to enforce it:


@Interceptor @RequireRole
public class AuthInterceptor {
    @AroundInvoke
    public Object check(InvocationContext ctx) {
        // Manually check roles
        // ...
    }
}

This works, but you're reinventing a standard feature.

🛡️ Authorization: The Easy Way

With Standard Jakarta EE Annotations

Use the standard `@RolesAllowed` annotation. No custom interceptor needed for simple role checks.


import jakarta.annotation.security.RolesAllowed;

@Path("/patients")
public class PatientResource {

    @GET
    @RolesAllowed({"DOCTOR", "NURSE"})
    public Response getAllPatients() {
        // ...
    }

    @POST
    @RolesAllowed("DOCTOR")
    public Response createPatient(Patient p) {
        // ...
    }
}

Simple, Standard, and Portable

This is the recommended approach for role-based access control (RBAC).

🚀 Extending the Standard for ABAC

What if roles aren't enough?

We can still use an interceptor for advanced Attribute-Based Access Control (ABAC).


@RequireAttribute(name = "department", value = "Cardiology")
@RolesAllowed("DOCTOR") // Combine standard and custom!
public Response getCardiologyRecords() { ... }

// The interceptor now only handles ABAC
@Interceptor @RequireAttribute
public class AuthorizationInterceptor {
    @Inject
    private JsonWebToken jwt; // Inject the validated token

    @AroundInvoke
    public Object checkAttributes(InvocationContext ctx) {
        // 1. Get the required attribute from annotation
        // 2. Get the user's attributes from the injected JWT
        // 3. Compare them and grant/deny access
    }
}

This is the power of Jakarta Security: use the standard where you can, extend where you must.

🔐 Multi-Factor Authentication (MFA)

Adding Another Layer of Zero Trust Verification


@ApplicationScoped
public class MfaService {
    public String generateOtp(String username, String ipAddress) {
        String otp = generateRandomOtp(); // 6-digit OTP
        storeOtp(username, otp, 5_MINUTES);
        return otp; // Send via SMS/Email/Authenticator
    }

    public boolean validateOtp(String username, String otp, String ipAddress) {
        OtpData stored = otpStorage.get(username);
        if (stored != null && !stored.used() && !isExpired(stored)) {
            return stored.otp().equals(otp);
        }
        return false;
    }
}

Zero Trust Principle: Verify Explicitly

MFA adds context-aware verification beyond passwords. Even with valid credentials, additional proof is required.

🔒 Encrypted Data Transit

Custom Security Annotations for TLS Enforcement


@InterceptorBinding
@Retention(RUNTIME)
@Target({METHOD, TYPE})
public @interface Encrypted {
    Algorithm algorithm() default Algorithm.AES_256_GCM;
    boolean requireTls() default true;
}

@GET @Path("/{id}")
@RolesAllowed({"DOCTOR", "NURSE"})
@Audited(action = "VIEW_PATIENT", level = CRITICAL)
@Encrypted(algorithm = AES_256_GCM) // Enforce TLS!
public Response getPatient(@PathParam("id") String id) {
    // Access to sensitive patient data
}

Zero Trust Principle: Never Trust the Network

The @Encrypted interceptor validates HTTPS/TLS for all sensitive operations. Plain HTTP requests are rejected with 403 Forbidden.

⚡ Performance Metrics

Maintaining Performance While Enforcing Security

Security Metrics


@GET @Path("/metrics/security")
@RolesAllowed({"ADMIN", "DOCTOR", "NURSE"})
public Response getSecurityMetrics() {
    return Response.ok(Map.of(
        "authSuccess", authSuccessCounter.getCount(),
        "authFailure", authFailureCounter.getCount(),
        "authzFailure", authzFailureCounter.getCount(),
        "suspiciousActivity", suspiciousCounter.getCount()
    )).build();
}

System Performance


@GET @Path("/metrics/performance")
@RolesAllowed("ADMIN")
public Response getPerformanceMetrics() {
    return Response.ok(Map.of(
        "uptime", runtimeBean.getUptime(),
        "heapUsagePct", heapUsed/heapMax*100,
        "cpuCores", osBean.getAvailableProcessors(),
        "systemLoad", osBean.getSystemLoadAverage()
    )).build();
}

Zero Trust doesn't mean slow. Monitor performance to ensure security measures don't impact user experience.

⚠️ From Demo to Production

What This Demo Includes vs What Production Needs

✓ Demo Implements

  • ✓ Rate limiting (5/min per IP, 10/5min per user)
  • ✓ Token revocation with cleanup scheduler
  • ✓ Session management with timeout enforcement
  • ✓ Persistent audit logs (database-backed)
  • ✓ MFA with OTP generation/validation
  • ✓ Security event monitoring with metrics
  • ✓ TLS/HTTPS enforcement via interceptors

✗ Demo Simplifies

  • In-memory storage (vs Redis/distributed cache)
  • OTP returned in response (demo mode)
  • Basic anomaly detection (vs ML-based)
  • Config file secrets (vs vault integration)

Production Hardening Needed

  • Distributed state: Redis for rate limits, sessions, revocation across instances
  • Secret management: HashiCorp Vault or AWS Secrets Manager
  • MFA delivery: SMS/Email/TOTP apps (not API response)
  • Advanced monitoring: ML-based anomaly detection, SIEM integration
  • Compliance: GDPR/HIPAA audit retention, data masking
  • High availability: Database replication, cache clustering
  • DDoS protection: Web application firewall (WAF)

Key Point: Demo shows production-grade patterns with simplified infrastructure. Scale and harden for your environment.

🎓 Key Takeaways

  1. Zero Trust is not optional - Modern threats require continuous verification
  2. Jakarta Security provides standard interfaces - `HttpAuthenticationMechanism`, `IdentityStore`, `@RolesAllowed`
  3. MicroProfile JWT handles token validation - Configure once, inject everywhere
  4. Use standards first, extend where needed - RBAC is standard, ABAC/MFA/Encryption are extensions
  5. MFA adds verification layers - Context-aware security beyond passwords
  6. Encrypted transit is enforced - Custom annotations validate TLS/HTTPS
  7. Performance monitoring matters - Security shouldn't sacrifice user experience
  8. Defense in depth with CDI - Events, interceptors, and metrics for continuous monitoring
